[Azure Storage](/azure/storage/common/storage-introduction) は、現代のデータ ストレージのシナリオに応える Microsoft のクラウド ストレージ ソリューションです。Azure Storage は、データ オブジェクト向けの非常にスケーラブルなオブジェクト ストアを提供します。クラウド向けのファイル システム サービス、信頼性の高いメッセージングのためのメッセージング ストア、NoSQL ストアも提供します。

Azure Storage は AI 対応のサービスで、ファイル、メッセージ、テーブルなど、さまざまな種類の情報を保存できます。Azure Storage は、ファイル共有のようなアプリケーションに使えます。開発者は作業データの保存に Azure Storage を使います。作業データには、Web サイト、モバイル アプリ、デスクトップ アプリケーションが含まれます。Azure Storage は、IaaS の仮想マシンや PaaS のクラウド サービスからも利用されます。

### Azure Storage について知っておくべきこと

Azure Storage は、構造化データ、非構造化データ、仮想マシン データという 3 つのカテゴリのデータをサポートすると考えることができます。次のカテゴリを確認し、自分の組織でどの種類のストレージが使われているか考えてみてください。

:::image type="content" source="../media/storage-types.png" alt-text="仮想マシン データ、非構造化データ、構造化データの図。":::


| カテゴリ | 説明 | ストレージの例 |
| --- | --- |
| **仮想マシン データ** | 仮想マシン データのストレージには、ディスクとファイルが含まれます。ディスクは、Azure IaaS 仮想マシン向けの永続的なブロック ストレージです。ファイルは、クラウド上のフル マネージドなファイル共有です。 | 仮想マシン データのストレージは、Azure マネージド ディスクを通じて提供されます。データ ディスクは、データベース ファイル、Web サイトの静的コンテンツ、カスタム アプリケーションのコードといったデータの保存に仮想マシンが使います。追加できるデータ ディスクの数は、仮想マシンのサイズによって決まります。 |
| **非構造化データ** | 非構造化データは、最も整理されていないデータです。非構造化データの形式は「非リレーショナル」と呼ばれます。 | 非構造化データは、Azure Blob Storage と Azure Data Lake Storage を使って保存できます。Blob Storage は、非常にスケーラブルな REST ベースのクラウド オブジェクト ストアです。Azure Data Lake Storage は、サービスとしての Hadoop 分散ファイル システム (HDFS) です。 |
| **構造化データ** | 構造化データは、共通のスキーマを持つリレーショナル形式で保存されます。構造化データは多くの場合、行、列、キーを持つデータベース テーブルに格納されます。テーブルは自動スケールする NoSQL ストアです。 | 構造化データは、Azure Table Storage、Azure Cosmos DB、Azure SQL Database を使って保存できます。Azure Cosmos DB は、グローバルに分散されたデータベース サービスです。Azure SQL Database は、SQL 上に構築されたフル マネージドの Database as a Service です。 |

### Azure Storage を使う際に考慮すべきこと

Azure Storage の構成計画を考える際は、次の主要な機能を考慮してください。

- **持続性と可用性を考慮する**: Azure Storage は持続性と高可用性を備えています。冗長性により、一時的なハードウェア障害の間もデータは安全に保たれます。ローカルの大災害や自然災害から保護するために、データセンター間や地理的リージョン間でデータをレプリケートできます。レプリケートされたデータは、予期しない障害の間も高い可用性を保ちます。

- **安全なアクセスを考慮する**: Azure Storage はすべてのデータを暗号化します。誰がデータにアクセスできるかを、きめ細かくコントロールできます。

- **スケーラビリティを考慮する**: Azure Storage は、現代のアプリケーションのデータ ストレージとパフォーマンスのニーズに応えられるよう、非常にスケーラブルに設計されています。

- **管理のしやすさを考慮する**: Microsoft Azure が、ハードウェアの保守、更新、重大な問題への対応を代行してくれます。

- **データへのアクセスのしやすさを考慮する**: Azure Storage 内のデータには、世界中のどこからでも HTTP または HTTPS でアクセスできます。Microsoft は、さまざまな言語向けの Azure Storage SDK を提供しています。.NET、Java、Node.js、Python、PHP、Ruby、Go、REST API を利用できます。Azure Storage は、Azure PowerShell や Azure CLI でのスクリプト実行もサポートします。Azure portal と Azure Storage Explorer は、データを視覚的に扱える手軽なソリューションです。

- **SFTP のサポートを考慮する**: Blob Storage では SFTP (SSH ファイル転送プロトコル) が使えるため、既存の SFTP ツールをそのまま使って BLOB との間で直接ファイルを移動できます。SFTP を使うには、階層型名前空間 (HNS) を有効にします。ストレージ アカウントの作成時 ([詳細設定] タブ) に有効にすることも、後から [設定] → [構成] で有効にすることもできます。

- **NFSv3 プロトコルのサポートを考慮する**: Blob Storage には NFSv3 でもアクセスでき、Linux クライアントがコンテナーを NFS 共有のようにマウントできます。NFSv3 は、Linux のファイル ワークロードから Azure への移行を簡単にします。

- **既定の認可方法を考慮する**: Azure portal では、**[Microsoft Entra 認可を既定にする]** を有効にできます。この認証により、共有アクセス キーの代わりにロールベースのアクセス制御 (RBAC) が既定になり、セキュリティを向上できます。
