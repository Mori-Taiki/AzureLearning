Azure App Service には、[認証と認可](/azure/app-service/overview-authentication-authorization)のサポートが組み込まれています。Web アプリ、API、モバイル バックエンド、さらには Azure Functions のアプリでも、ほとんど (あるいはまったく) コードを書かずに、ユーザーのサインインとデータへのアクセスを実現できます。

> [!VIDEO https://learn-video.azurefd.net/vod/player?id=b69ed6c4-3890-4947-9543-f441a4f4c7e0]

安全な認証と認可には、フェデレーション、暗号化、JSON Web トークン (JWT) の管理、許可の種類 (grant type) など、セキュリティへの深い理解が必要です。App Service はこれらの機能を提供してくれるため、顧客へのビジネス価値の提供により多くの時間と労力を注げます。

> [!NOTE]
> 認証と認可に必ず Azure App Service を使わなければならないわけではありません。多くの Web フレームワークにはセキュリティ機能が同梱されており、好みのサービスを使ってかまいません。

### App Service によるアプリのセキュリティについて知っておくべきこと

App Service がアプリのセキュリティ確保をどう支援するのか、詳しく見てみましょう。

- Azure App Service の認証・認可セキュリティ モジュールは、アプリケーション コードと同じ環境で、しかし分離されて動作します。

- セキュリティ モジュールはアプリ設定で構成します。SDK も、特定の言語も、アプリケーション コードの変更も必要ありません。

- セキュリティ モジュールは、アプリのために次のようなタスクを処理します。
   - 指定したプロバイダーによるユーザーの認証
   - トークンの検証、保存、更新
   - 認証済みセッションの管理
   - リクエスト ヘッダーへの ID 情報の挿入

### App Service でアプリのセキュリティを確保する際に考慮すべきこと

App Service の認証・認可のセキュリティは、Azure portal で機能を選ぶことで構成します。次のオプションを確認し、自分の App Service アプリの実装にどのセキュリティが役立つか考えてみてください。

- **匿名リクエストを許可する (アクションなし)**: 未認証トラフィックの認可をアプリケーション コードに委ねます。認証済みのリクエストについては、App Service が HTTP ヘッダーで認証情報も渡します。この機能により、匿名リクエストの扱いに柔軟性が生まれます。この機能を使えば、複数のサインイン プロバイダーをユーザーに提示できます。

- **認証済みリクエストのみを許可する**: すべての匿名リクエストを、選択したプロバイダーの `/.auth/login/<provider>` へリダイレクトします。この機能は **[\<プロバイダー\> でログイン]** と同等です。匿名リクエストがネイティブのモバイル アプリからのものである場合、返されるレスポンスは `HTTP 401 Unauthorized` メッセージです。この機能を使えば、アプリに認証コードをまったく書く必要がありません。

   > [!Important]
   > この機能は、アプリへの**すべて**の呼び出しへのアクセスを制限します。多くのシングルページ アプリのように、アプリに公開のホーム ページが必要な場合、すべての呼び出しを制限するのは望ましくないかもしれません。

- **ログとトレース**: 認証と認可のトレースを、ログ ファイルで直接確認できます。想定外の認証エラーが出た場合も、既存のアプリケーション ログを見れば詳細をすべて確認できて便利です。失敗した要求のトレースを有効にすれば、失敗したリクエストにセキュリティ モジュールがどう関与したかを正確に確認できます。トレース ログでは、`EasyAuthModule_32/64` という名前のモジュールへの言及を探してください。
